--------------------------------------------------------------------------------
1. PROPOSITO Y ALCANCE
--------------------------------------------------------------------------------
Recolectar evidencia forense de VMs Windows afectadas por ransomware, sin
conectividad de red durante la adquisicion y sin causar mas cifrado.
Resultado final: uno o mas ZIPs (.zip) + sus hashes SHA-256 + un archivo
de notas por VM, entregados al equipo de respuesta.

--------------------------------------------------------------------------------
1.5 COMPATIBILIDAD DE SISTEMAS OPERATIVOS
--------------------------------------------------------------------------------
KAPE 1.3.0.2 es una aplicacion .NET Framework 4.5.2. Funciona en:

  Windows 11 (todos los builds actuales)
  Windows 10 (1809+)
  Windows 8.1, Windows 8
  Windows 7 SP1 (con .NET 4.5.2 instalado)
  Windows Server 2022 / 2019 / 2016 / 2012 R2 / 2012
  Windows Server 2008 R2 SP1 (con .NET 4.5.2 instalado)

Notas importantes:
- Win7 SP1 viene por defecto con .NET 4.0, no 4.5.2. KAPE no arranca
  hasta que se instale .NET 4.5.2 via Windows Update KB2934520.
  Use CHECK_COMPAT.cmd para validar antes de correr KAPE_TRIAGE.
- PowerShell 2.0 viene en Win7 por defecto y es suficiente para el
  script. PowerShell 3.0+ recomendado.
- wmic esta deprecated en Win11 24H2 pero sigue funcional en todos
  los builds actuales. Si en algun momento desaparece, use el modo
  manual descrito en la seccion 7.
- Si la VM es Windows XP o Vista, KAPE no esta soportado. Necesita
  otro metodo (live CD linux + FTK Imager o similar).

Antes de correr KAPE_TRIAGE_UI.exe, abra la UI y verifique el pre-flight
(los checks aparecen en verde "OK" o rojo "FAIL"). Si todo OK, el boton
"Ejecutar adquisicion" se habilita.

--------------------------------------------------------------------------------
2. RIESGOS Y PRECAUCIONES (lea antes de tocar nada)
--------------------------------------------------------------------------------
- NO conecte ninguna NIC. "Connected" = NO, "Connect at power on" = NO.
- NO habilite RDP, SMB, WinRM, SSH ni consola remota.
- NO conecte shares NFS/SMB/iSCSI desde el host hipervisor hacia la VM.
- NO use USB passthrough. Todo entra por la ISO montada como CD/DVD.
- NO inicie sesion con cuentas privilegiadas innecesarias.
- NO ejecute chkdsk, repair, cleanup, Windows Update, "Scan and fix",
  antivirus manual ni cualquier herramienta que modifique el sistema.
- NO borre, revierta ni consolide snapshots antes de preservar el estado.
- NO marque "Delete from storage" / "Delete files from datastore" al
  desconectar el disco de salida.
- Si Windows o el hipervisor ofrecen "Initialize disk" sobre un disco
  existente, DETENGASE y avise al equipo de respuesta.
- NO reanude una VM suspendida ni con snapshots de memoria: la pagina de
  RAM puede contener claves y evidencia volatil que se pierde.
- Riesgo operativo: al arrancar la VM el ransomware puede volver a
  ejecutarse. Por eso:
    a) Si la VM esta apagada y puede clonarse, HAGALO y trabaje sobre el
       clon.
    b) Si no puede clonarse, arranque SOLO lo necesario para montar la
       ISO, ejecutar KAPE y apagar.
    c) Minimice el numero de discos adicionales conectados.

3. PREPARACION PREVIA
--------------------------------------------------------------------------------
- Confirme estado de la VM: APAGADA o suspendida.
- Si puede clonar la VM, clonela con la VM APAGADA. Asi trabajara sobre
  el clon.
- Confirme que la NIC esta removida o desconectada y que "Connect at
  power on" esta desactivado.
- Confirme que no hay adaptadores de red adicionales.
- Confirme la zona horaria del host del hipervisor y la fecha del sistema.

5. FLUJO RAPIDO (RECOMENDADO) — UI visual o consola
--------------------------------------------------------------------------------
Por VM:

5.1  Montar la ISO como CD/DVD virtual:
     - Proxmox:  Hardware -> CD/DVD Drive -> Use CD/DVD disc image file ->
                Storage: local -> ISO image: CYBOLT-DFIR-TRIAGE-v5.2.13.iso.
     - ESXi:     Edit settings -> CD/DVD drive -> Datastore ISO file ->
                Browse -> DFIR/CYBOLT-DFIR-TRIAGE-v5.2.13.iso.
     Verificar que el CD este visible dentro de la VM al arrancar.

5.2  (Solo la primera vez o si el VMDK es nuevo) Crear y formatear el
     disco de salida (label DFIR_OUTPUT):
     - Proxmox:  Hardware -> Hard Disk -> SCSI/SATA: 0 -> Add ->
                local-lvm (o local), tamano 50-100 GB, formato qcow2 o raw.
     - ESXi:     Edit settings -> Add hard disk -> New standard hard disk ->
                Tamano recomendado: 50 GB (80-100 GB si EventLogs grandes),
                Provisioning: Thick lazy zeroed o Thin provisioned.
     Encender VM -> diskmgmt.msc -> Initialize Disk (GPT) ->
       New Simple Volume -> NTFS -> Volume label: DFIR_OUTPUT.
     Asignar letra (normalmente E:).
     Verificar: wmic logicaldisk get DeviceID,VolumeName,FileSystem

     En corridas subsiguientes el disco ya esta inicializado y formateado:
     solo conectarlo y arrancar.

5.3  Encender la VM.

5.4  En el Explorador de archivos, ir al CD/DVD ("CYBOLT-DFIR-TRIAGE").

5.5  Elegir UNA de las dos opciones:

      OPCION A - VISUAL (RECOMENDADA):
      --------------------------------
        Doble clic en KAPE_TRIAGE_UI.exe.
        - Windows pide elevacion (UAC). Aceptar SI (corre como Admin).
        - Espera a que termine el pre-flight (los checks aparecen en
          verde con "OK" o en rojo con "FAIL").
        - ComboBox "Particion de salida" debe mostrar E: (DFIR_OUTPUT).
          ComboBox "Particion fuente" debe mostrar C:.
          Si no es asi, ajustar manualmente antes de Ejecutar.
        - Click "Ejecutar adquisicion".
        - Observa el log en tiempo real y el strip de 6 fases arriba.
        - Al terminar, aparece el SHA-256 y tamano del ZIP en la barra
          de estado, junto con la ruta del ZIP generado.

      OPCION B - CONSOLA (FALLBACK):
      ------------------------------
        Doble clic en CHECK_COMPAT.cmd para verificar requisitos primero.
        Si todo OK, doble clic en KAPE_TRIAGE.cmd.
        - Si Windows pide elevacion (UAC), aceptar SI.
        - Confirmar el resumen con "SI".
        - Esperar. Al final aparecera el SHA-256 y el tamano del ZIP.

5.6  Apagar la VM (Shutdown).

5.7  Desconectar el disco de salida:
     - Proxmox:  Hardware -> Hard Disk (sata0/SCSI con DFIR-OUTPUT) ->
                Detach. NO marcar "Delete from storage".
     - ESXi:     Edit settings -> seleccionar el disco de salida ->
                "Remove from virtual machine"  (NO "delete from datastore").

--------------------------------------------------------------------------------
6. QUE HACE KAPE_TRIAGE_UI.exe (paso a paso interno)
--------------------------------------------------------------------------------
Si necesita entender que esta pasando o si algo falla, esto es lo que
la UI ejecuta:

  1. Pide elevacion a Administrador via manifest requireAdministrator.
  2. Auto-detecta la unidad del CD (AppDomain.BaseDirectory) y la
     unidad con label "DFIR_OUTPUT" (wmic logicaldisk).
  3. Pre-flight: chequea wmic, certutil, kape.exe, Targets/, espacio.
  4. STAGING: copia D:\kape.exe -> E:\_kape_stage\kape.exe. Esto evita
     el bug original donde KAPE escribe Modules\bin debajo de su propio
     Assembly.Location (D:\) y falla con "Access denied [D:]".
  5. Calcula hostname + fecha + hora para nombres de archivo unicos.
  6. Muestra resumen (Source, Target, ISO, Output, ZIP) en el panel.
  7. Pide confirmacion con el boton "Ejecutar".
  8. Ejecuta kape.exe desde E:\_kape_stage\ con:
       --tsource C:
       --target KapeTriage
       --tdest "<output_drive>{HOSTNAME}-KAPE-{YYYYMMDD}-{HHMMSS}"
       --targetdir "<iso_drive>\Targets"
       --zip "<output_drive>{HOSTNAME}-KAPE-{YYYYMMDD}-{HHMMSS}.zip"
       --hv nc,vm --sync $Null --gui
  9. Calcula SHA-256 del ZIP con certutil y lo guarda al lado.
 10. Escribe notas en E:\NOTES\{HOSTNAME}-NOTES-{YYYYMMDD}.txt.
 11. Persiste el log completo en E:\NOTES\{HOSTNAME}-LOG-{YYYYMMDD}.txt.

--------------------------------------------------------------------------------
7. SI LA UI NO FUNCIONA (modo manual)
--------------------------------------------------------------------------------
Si KAPE_TRIAGE_UI.exe no arranca (UAC bloqueado, sin .NET 4.5.2,
entorno raro), puede ejecutar KAPE manualmente. Reemplace <LETRA_ISO>
y <LETRA_OUTPUT> por las letras reales de su sistema.

7.1  Identificar letras:
     powershell :  Get-Volume | Format-Table DriveLetter, FileSystemLabel
     cmd        :  wmic logicaldisk get DeviceID,VolumeName,FileSystem
     diskpart   :  list volume

7.2  Validar target:
     "<LETRA_ISO>:\kape.exe" --target KapeTriage --tlist

7.3  Simular tamano:
     "<LETRA_ISO>:\kape.exe" --tsource C: --target KapeTriage ^
         --tdest "<LETRA_OUTPUT>:\<HOSTNAME>-KAPE-20260923-120000" ^
         --targetdir "<LETRA_ISO>:\Targets" --sim

7.4  Ejecutar (lanzar desde una copia escribible, NO desde el CD):
     mkdir "<LETRA_OUTPUT>:\_kape_stage"
     copy "<LETRA_ISO>:\kape.exe" "<LETRA_OUTPUT>:\_kape_stage\kape.exe"
     cd /d "<LETRA_OUTPUT>:\_kape_stage"
     kape.exe --tsource C: ^
         --target KapeTriage ^
         --tdest "<LETRA_OUTPUT>:\<HOSTNAME>-KAPE-20260923-120000" ^
         --targetdir "<LETRA_ISO>:\Targets" ^
         --zip "<LETRA_OUTPUT>:\<HOSTNAME>-KAPE-20260923-120000.zip" ^
         --hv nc,vm --sync $Null --gui

7.5  Calcular hash:
     certutil -hashfile "<LETRA_OUTPUT>:\<HOSTNAME>-KAPE-20260923-120000.zip" SHA256
     echo <HASH>  <HOSTNAME>-KAPE-20260923-120000.zip > "<LETRA_OUTPUT>:\<HOSTNAME>-KAPE-20260923-120000.zip.sha256"

--------------------------------------------------------------------------------
8. SALIDAS ESPERADAS TRAS TERMINAR
--------------------------------------------------------------------------------
Dentro de la unidad DFIR_OUTPUT (normalmente E:):

  {HOSTNAME}-KAPE-YYYYMMDD-HHMMSS.zip          Resultado principal.
  {HOSTNAME}-KAPE-YYYYMMDD-HHMMSS.zip.sha256   Hash SHA-256 (mismo dir).
  NOTES\{HOSTNAME}-NOTES-YYYYMMDD.txt          Contexto de la corrida.
  NOTES\{HOSTNAME}-LOG-YYYYMMDD.txt            Log completo.
  _kape_stage\                                  Binarios copiados + Modules\bin
                                                generado por KAPE.

Si la misma VM se corre varias veces el mismo dia, cada corrida produce
archivos distintos (sufijo HHMMSS). No hay colisiones.

--------------------------------------------------------------------------------
10. CAPTURA DE RAM (Opcion A: GUI - Opcion B: batch fallback)
--------------------------------------------------------------------------------
Si el incidente lo justifica (ransomware con persistencia, credenciales
en memoria, conexiones activas, etc.), capturar la RAM ANTES de correr
KapeTriage. La GUI RAM_CAPTURE_UI.exe v5.2.17 es la ruta recomendada.
El batch CAPTURE_RAM.cmd queda como fallback si no se puede lanzar GUI.

10.1 Opcion A (GUI - recomendada):
  a) Montar CYBOLT-DFIR-TRIAGE-v5.2.18.iso como CD-ROM en la VM afectada.
  b) Encender la VM. Aceptar el prompt UAC que aparece al lanzar la
     GUI (manifest requireAdministrator).
  c) Click derecho en D:\RAM_CAPTURE_UI.exe -> "Ejecutar como
     administrador" (o doble click si UAC esta habilitado).
  d) La UI auto-detecta:
       - Letra del CD-ROM donde esta Tools\Memory\winpmem_mini_x64_rc2.exe
         (con ComboBox de fallback si hay varios).
       - Particion de salida (label DFIR_OUTPUT; ComboBox permite elegir
         otra si hay varias).
       - Hostname, fecha, RAM total detectada.
     Log muestra [OK] o "(binario no encontrado)" al lado de cada CD-ROM.
  e) Validar en la UI:
       - Ruta del archivo de salida (default: E:\RAM-<HOSTNAME>-<DATETIME>.raw).
       - Espacio libre suficiente (RAM + 10% overhead). Si no alcanza,
         la UI pide confirmacion antes de continuar.
  f) Click "Iniciar captura de RAM". Confirmacion final.
  g) Durante la captura (~5-15 min):
       - ProgressBar se actualiza desde lineas de winpmem (regex %).
       - Log en vivo (stdout/stderr de winpmem).
       - Boton "Cancelar" mata el proceso winpmem si es necesario.
  h) Al terminar:
       - SHA-256 se calcula con System.Security.Cryptography.SHA256
         nativo (streaming, sin subprocess).
       - Se escribe companion {output}.sha256 (formato standard).
       - UI muestra tamano + SHA-256 + tiempo transcurrido.
       - Boton "Verificar SHA-256" permite re-calcular el hash post-captura.

10.2 Opcion B (batch - fallback si GUI no aplica):
  a) Mismo prerequisito: ISO montada como CD-ROM.
  b) cmd.exe como Administrator.
  c) D:\Tools\Memory\CAPTURE_RAM.cmd [OUTDIR]
     (default OUTDIR = E:\; acepta otra letra como argumento).
  d) El script valida admin, valida binario, pide confirmacion, ejecuta
     winpmem, calcula SHA-256 con certutil, escribe companion .sha256.
  e) Logica identica al final (mismo nombre de archivo, mismo SHA-256
     algoritmo equivalente).

10.3 Recomendacion de cadena de custodia:
  - Capturar RAM ANTES de KapeTriage (estado mas cercano al incidente).
  - Capturar RAM y KAPE ZIP en el mismo disco de salida (DFIR-OUTPUT.vmdk).
  - Conservar el archivo .raw y el .sha256 juntos al entregar al analista.
