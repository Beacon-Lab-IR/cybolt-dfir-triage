FLUJO DE CAPTURA DE RAM (Opcion A: GUI - Opcion B: batch fallback)
-------------------------------------------------------------------
  1. Operador monta KAPE-MEDIA-v5.2.18.iso como CD-ROM en la VM
     afectada (sin red, VMDK DFIR_OUTPUT adjunto como segundo disco).
  2. Si quiere GUI: abre cmd como Administrator, navega a la ISO,
     doble clic en RAM_CAPTURE_UI.exe. Acepta UAC.
     Si GUI no aplica: doble clic en D:\Tools\Memory\CAPTURE_RAM.cmd.
  3. La GUI auto-detecta:
       - Letra del CD-ROM (con ComboBox si hay varios).
       - Particion de salida (label DFIR_OUTPUT; ComboBox si varias).
       - Hostname, fecha, RAM total detectada (suma de sticks fisicos).
  4. Operador valida y click "Iniciar captura de RAM".
  5. UI valida espacio libre (RAM + 10%), pide confirmacion, lanza
     winpmem con Process, redirige stdout/stderr al TextBox, parsea
     progreso a ProgressBar.
  6. Al terminar (exit 0), SHA-256 se calcula con
     System.Security.Cryptography.SHA256 streaming. Se escribe
     companion {output}.sha256.
  7. UI muestra tamano + SHA-256 + tiempo transcurrido. Boton
     "Verificar SHA-256" permite re-calcular post-captura.

  Si winpmem falla con exit code != 0:
     - v5.2.18 abre MessageBox expandido con:
         * Tamano del archivo .raw parcial (si existe).
         * Ultimas 25 lineas de stdout.
         * Ultimas 25 lineas de stderr.
         * Lista de causas comunes: Defender/AV en tiempo real,
           LSASS Protection / Credential Guard, politica de grupo
           restringiendo drivers, disco lleno.

  El binario winpmem_mini_x64_rc2.exe es de Velocidex / WinPmem
  v4.0.rc1 (firmado Microsoft), 527 KB, 64-bit. Funciona en
  Windows 7 SP1+ / Server 2008 R2+.
